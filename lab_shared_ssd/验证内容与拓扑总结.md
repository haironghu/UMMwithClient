# 共享盘 + 混合池实验：验证内容与拓扑总结

> 环境：openEuler 宿主机 + QEMU 8.2（TCG）双 VM；VM1=10.0.0.11（ummD+umms+客户端A/node0），
> VM2=10.0.0.12（客户端B/node1）；两块 8G NVMe 模拟盘（同一 raw 后备文件，`file.locking=off`）。
> 拓扑图见同目录 `混合池拓扑图.png`。

## 1. 实验形态与拓扑

```
        宿主机 openEuler（QEMU 8.2 TCG，NVMe 模拟）
 ┌───────────────────────┐   p2p 网段    ┌───────────────────────┐
 │ VM1  10.0.0.11        │  10.0.0.0/24  │ VM2  10.0.0.12        │
 │  ummD :20001（元数据） │◄═════════════►│  （仅客户端）          │
 │  umms :20002（分配权威）│  控制面 RPC   │                       │
 │  客户端A node0         │  alloc/free   │  客户端B node1         │
 │  ├ DRAM层 malloc 512M  │               │  ├ DRAM层 malloc 512M  │ ← 私有
 │  └ SSD面 mmap 本机盘   │               │  └ SSD面 mmap 本机盘   │
 └───────┬───────┬───────┘               └───────┬───────┬───────┘
         │       │  数据面：本机 mmap，不过网络   │       │
      ┌──▼───────▼──┐                         ┌──▼───────▼──┐
      │ ssd0.raw 8G │◄════ 同一后备文件 ══════►│ ssd1.raw 8G │
      └─────────────┘    （file.locking=off）   └─────────────┘
```

- **控制面**：两 VM 客户端经 RPC 向 VM1 的 umms 申请/释放 chunk（ummD 提供元数据/拓扑视图）——唯一过网络的部分。
- **数据面**：全程本机。SSD 层 = `open + mmap(MAP_SHARED)` 裸设备 memcpy；内存层 = 本机 malloc buffer。不设 `peer_nodes`，remote transport 不挂载（opt-in 门槛）。
- **"共享"的真相**：两个 QEMU 进程打开宿主上同一 raw 文件；NVMe 协议本身无多主机一致性，安全性由 umms 发放**互不相交的 offset 区间**保证。
- **GPA**：`node[63:58] | tier[57:56] | offset[55:0]`；tier 0=DRAM、1=CXL、2=SSD。

## 2. 已验证内容

### 2.1 共享盘基础能力 —— 双 VM 端到端 PASS（已在实验机跑通）

| 验证点 | 方法 | 证据/断言 |
|---|---|---|
| 拓扑可见性 | S0：客户端查 ummD 全局视图 | 两 VM 均看到两块 SSD 资源 |
| 分配-写读一致性 | S1：各申请 2×3G chunk，1MB piece 流式写确定性 pattern（含节点 tag+chunk_id），读回逐字节校验 | 全 PASS；3G chunk 跨 8G 设备边界，覆盖跨设备分段路径 |
| 分配权威唯一性 | A2：回收两侧结果 JSON，集群级断言所有 chunk `[offset, offset+size)` 两两不相交 | 4 chunk 交错（vmB/vmA/vmB/vmA）无重叠 |
| 数据面不越网 | A3：断言客户端日志无 `remote transport attached` | PASS（未配 peer_nodes，remote 不挂载） |
| 盘上数据真实性 | A4（单机仿真）：按 offset 把 chunk 映射回 raw 文件逐字节比对 pattern | PASS，含跨设备分段 |
| 负路径三件套 | S3：超额申请 → NO_MEMORY；越界写 → 拒绝；重复释放 → 拒绝 | PASS |

### 2.2 混合池（SSD + DRAM，无 CXL 硬件）—— 代码完成，沙箱验证 PASS，VM 端到端待重跑

| 验证点 | 方法 | 状态 |
|---|---|---|
| 路线A（零代码） | `EXP_MEM_TIER=1`：内存层占 mock CXL 槽（无 `/dev/cxl/mem0` 自动回退 malloc 后备=事实 DRAM） | 沙箱 smoke PASS（GPA tier=1, `0x0500...`） |
| 路线B（真 DRAM tier） | `MEM_TIER_KIND=dram EXP_MEM_TIER=0`：`mem_service_direct_create_tiered` 注册 DRAM 槽 + `tier_router_set_dram` + `UMMConfig.local_mem_as_dram`（复用 `_reserved_phase1[0]`，ABI 零影响，sizeof=7448 已验证） | 沙箱 smoke PASS（GPA tier=0, `0x0400...`），S1m/S3/S4 全 PASS |
| 内存层写读一致性 | S1m：内存层分配 + 流式写读逐字节校验 | PASS |
| tier 容量隔离 | S4：双向互测——内存层超额不影响 SSD 层分配，反之亦然 + 内存层负路径 | PASS |
| 回归无损 | 15 个测试套件 0 失败；sim A1-A4 全 PASS | PASS |

**关键语义结论**（两层不要混用结论）：

| | SSD 层 | 内存层 |
|---|---|---|
| 分配权威 | umms 全局位图 | umms 全局位图 |
| 数据面 | 两 VM **物理共享**（同一后备文件） | 各 VM **私有** malloc buffer |
| 跨 VM 可见 | 不相交前提下各自读写；可见性须 fence+invalidate（见 S5） | 互不可见（DRAM 本就不能跨机共享） |

内存层的池化语义是「全局分配 + 私有数据面」——umms 统一发 offset 配额，各 VM 写自己的内存；这不是 bug，是 DRAM 池化在无 CXL 硬件下的合理语义。

### 2.3 落盘/刷盘语义（S5）—— 代码完成，沙箱正路径 PASS，双 VM 负路径待跑

背景：SSD 数据面是 mmap+memcpy，写只进本 VM 页缓存；**B 的页缓存不会因 A 落盘自动失效**（两个独立内核，无解，必须读端主动丢弃）。

| 验证点 | 方法 | 状态 |
|---|---|---|
| fence 真落盘 | 修正：`umm_fence()` = CPU 屏障 + 全池 `msync(MS_SYNC)`（原实现只有屏障，不落盘）；libnvm/NDS 直驱后端天然跳过 | 沙箱 PASS |
| invalidate API | 新增 `umm_invalidate()` → `ssd_pool_invalidate()` → 逐设备 `msync(MS_INVALIDATE)`；非 SSD tier no-op | 沙箱 PASS |
| 正路径 | writer 写 pattern→fence 落盘（进程保活）→ B invalidate→读回，digest 逐字节一致 | 沙箱 B1-B4 全 PASS |
| 负路径（页缓存陷阱） | B 预读填旧视图→刷盘前读，预期读到陈旧数据 | **单机无法复现**（共享页缓存），只能双 VM 验证 |
| writer 保活设计 | fence 而非退出时 munmap 才是被验证的落盘路径 | 已落实到编排 |

### 2.4 共享内存窗口（S6，virtio-pmem）—— 代码完成，沙箱 C1-C3 全 PASS，双 VM 待跑

DRAM 层从「各 VM 私有」升级为「宿主共享物理页」：03 给两台 VM 挂同一份
`memory-backend-file,share=on` 后备 → VM 内 `/dev/pmem0` → mem_service
DAX mmap 直达。x86 硬件 cacheline 一致，**无需 S5 的 fence+invalidate**；
是 CXL 3.x G-FAM 的软件替身。

| 验证点 | 方法 | 状态 |
|---|---|---|
| 设备后备可配 | `MEM_TIER_BACKING=/dev/pmem0` → 03 挂盘 / 04 udev+容量校验 / 05 yaml `memory_device`；mem_service `mem_device` 参数，DRAM/CXL 两分支通吃，ABI 不变（复用 `cxl_device` 字段） | 沙箱 PASS |
| 防静默退化 | DRAM 设备后备 fail-hard（open/mmap 失败直接报错，**不回退 malloc**）；06 日志守卫 grep `falling back to malloc backing` | 沙箱 PASS |
| 硬件一致性 | B 按带外 GPA **直接读、不 invalidate**，digest 逐字节一致即 PASS（对照 S5 必须 invalidate） | 沙箱路线A+B C1-C3 全 PASS；双 VM 待跑 |

## 3. 过程中修复的工程防线（已固化进脚本）

1. **陈旧 `build_pic` 事故**：tar 把宿主旧 PIC 目标文件带进 VM，mtime 骗过 make，`libumm.so` 链出旧代码（服务端却是新代码，极具迷惑性）。修复：04 打包排除 `build/`+`build_pic/`、包内自检、VM 侧删 `.o`、编译后 `nm` 符号自检；辅以「日志行号=二进制指纹」甄别法。
2. **隐式声明段错误**：`mem_server.c` 调用新函数缺 extern 声明→指针截断→umms SIGSEGV。教训固化：构建零告警门禁。
3. **服务重启竞态**：pkill 大小写敏感 + 旧实例未死透就起新实例 → bind 失败。05 已加等待退出 + 端口验证。
4. **cloud-init/apt 失败静默放行**：新 VM 包装失败（出网代理问题）时 03 现在检查 `cloud-init status`，04 编译前预检工具链；`APT_PROXY` 旋钮注入 seed。
