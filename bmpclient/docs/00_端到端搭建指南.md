# UMM + bmpclient 端到端搭建指南

> 目标读者：首次部署本项目的工程师。
> 读完可完成：编译 → 单测 → mock 全链路 → 真机 SSD tier 全链路。

## 0. 项目结构

```
umm_bmpclient/
├── umm/            # C 基座：libumm + ummD/umms 服务端 + 测试
├── bmpclient/      # Python 客户端：并发引擎 + e2e 场景
└── docs/           # 架构文档（01-04）+ R6 遗留问题 + 本指南
```

## 1. 环境要求

| 项 | 要求 |
|---|---|
| OS | Linux（openEuler / CentOS / Ubuntu），x86-64 或 aarch64 |
| 编译器 | gcc（C11）、make |
| Python | ≥ 3.8（ctypes 标准库，无第三方依赖） |
| 真机 SSD 数据面 | 华为昇腾环境 + `libnvm_host.so`（同事 NPU_Direct_Storage 项目）+ 一块**专用闲置 NVMe 盘**（由 libnvm_helper 管理） |

## 2. 编译（2 分钟）

```bash
cd umm
make -j
# 产物：
#   build/libumm.a / build/libumm.so   （Python 客户端加载后者）
#   bin/ummd bin/umms                  （两个服务端）
#   bin/test_* bin/libnvm_host.so      （测试与桩库）
```

## 3. 单元测试（无盘环境全量可跑）

```bash
make test
# 预期：15 个测试程序全 PASS。
# 注：test_ssd_libnvm 已钉死桩库（libnvm_host.so 桩），
#     与 shell 里是否 export 真库路径无关。
```

## 6. 真机 libnvm 场景（生产形态）

### 6.1 前置检查

```bash
# 1) 确认真库及其传递依赖可加载（应无 not found 输出）：
export UMM_LIBNVM_PATH=/path/to/NPU_Direct_Storage/build/lib/libnvm_host.so
ldd $UMM_LIBNVM_PATH | grep "not found"
# 有缺失则把所在目录加入 LD_LIBRARY_PATH（常见：libruntime_common.so）

# 2) 确认盘身份：/dev/libnvm_helper0 背后是那块闲置盘（勿用系统盘！）
lsblk -d -o NAME,SIZE,MODEL
```

### 6.2 冒烟（零写入）

```bash
cd umm
UMM_TEST_LIBNVM_INITONLY=1 \
UMM_TEST_LIBNVM_CTRL="libnvm:/dev/libnvm_helper0@1" \
./bin/test_ssd_libnvm
# 预期：3 passed（init/free 冒烟，不写盘）
```

### 6.3 受控写入验证（窗口内）

```bash
UMM_TEST_LIBNVM_CTRL="libnvm:/dev/libnvm_helper0@1" \
UMM_TEST_LIBNVM_OFF=$((1024*1024*1024)) \
./bin/test_ssd_libnvm
# 预期：24 passed；写入严格限制在 [1GB, 1GB+16MB) 窗口
```

### 6.4 端到端服务场景

```bash
# 重要：真机必须 UMM_LIBNVM_CTXS=1（同进程多 init 会损坏 ctx，见 docs/R6）
UMM_LIBNVM_CTXS=1 \
python3 bmpclient/scripts/demo_e2e_ssd.py \
    --spec "libnvm:/dev/libnvm_helper0@1+0x40000000" --capacity 16G
# 预期：D0/D1/D2 全 PASS；全部落盘在窗口 [1GB, 1GB+16G)
```

### 6.5 手工起服务（排障/长期运行用）

```bash
# 终端1：元数据服务
./bin/ummd -p 20001 -b 0.0.0.0
# 终端2：内存服务（用模板配置，含 SSD tier）
export UMM_LIBNVM_PATH=... LD_LIBRARY_PATH=...
./bin/umms -c config/umms_ssd_libnvm.yaml
# 客户端随后按 6.4 的 client 部分连接
```

## 7. 配置速查

| 配置/环境变量 | 作用 | 缺省 |
|---|---|---|
| `umms.yaml: ssd_devices` | SSD 设备列表 `"path:size,..."` | 无 |
| `UMM_LIBNVM_PATH` | libnvm_host.so 绝对路径 | 按默认名 dlopen |
| `UMM_LIBNVM_CTXS` | 每后端 ctx 数（**真机固定 1**） | 4 |
| `UMM_TEST_LIBNVM_CTRL/OFF/INITONLY` | 真机测试开关（见 6.2/6.3） | 桩库模式 |
| `UMM_ROOT` / `UMM_BUILD_DIR` | e2e 脚本定位服务端/libumm.so | 自动探测 |

设备路径语法：`libnvm:<控制器>[@ns][+<窗口基址>]`
例：`libnvm:/dev/libnvm_helper0@1+0x40000000`

## 8. 常见问题（FAQ）

| 症状 | 处置 |
|---|---|
| `dlopen failed: libruntime_common.so not found` | 传递依赖缺失：`ldd` 查全缺失列表 → 目录加入 `LD_LIBRARY_PATH` |
| `libumm.so not found`（Python 侧） | `cd umm && make`（shared 已纳入默认目标）；或设 `UMM_BUILD_DIR` |
| `Invalid namespace or format` + 超时 | **多 init 自损**：`UMM_LIBNVM_CTXS=1` 重跑（见 docs/R6） |
| 测试在 /mnt 下 Permission denied | 分区 noexec：`cp bin/* /tmp && cd /tmp` 运行 |
| umms 起不来（端口未就绪） | SSD 设备打开失败：查 UMM_LIBNVM_PATH / 控制器占用（`fuser`）/ 窗口越界 |
| 拓扑里看不到 SSD | client 需 `tier_aware=True` + `enable_ssd()`；ummD 记录为空时返回空拓扑属正常 |
