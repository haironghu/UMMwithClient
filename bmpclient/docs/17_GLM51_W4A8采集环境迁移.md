# GLM-5.1 W4A8 Trace 采集环境迁移

本文恢复此前已经跑通的 vLLM-Ascend TP16、eager 启动配置。原会话使用的是 **W4A8（权重 4 bit、激活 8 bit）**，不是 W8A4。以下下载源和启动脚本面向昇腾；更换到 NVIDIA GPU 时，需要重新选择量化格式、框架和采集插桩。

## 1. 权重来源与下载

- [Eco-Tech/GLM-5.1-w4a8（ModelScope）](https://modelscope.cn/models/Eco-Tech/GLM-5.1-w4a8)
- [同名 Modelers 仓库](https://modelers.cn/models/Eco-Tech/GLM-5.1-w4a8)：[vLLM-Ascend v0.18.0 GLM 部署文档](https://docs.vllm.ai/projects/ascend/en/v0.18.0/tutorials/models/GLM5.html)给出的 W4A8 下载入口。

核对时 ModelScope 文件总量为 420,165,677,044 B（约 420.17 GB / 391.31 GiB），包含 99 个量化 safetensors 分片和 `quant_model_description.json`。配置为 `glm_moe_dsa`、78 层、`index_topk=2048`。这是当前公开可下载版本，无法仅凭旧目录名确认与此前下载的权重逐字节一致；重现实验需记录模型 revision、配置及量化描述。

选择容量足够的磁盘或共享文件系统，权重加上采集结果建议预留至少 500 GB，并根据 Trace 数量额外扩容。若空间仍紧张，减少采集层/step，而不是把权重放进容器临时层。

在新机器上、仓库根目录运行：

```bash
# 如果尚未安装 ModelScope，在下载环境安装即可；不要为下载升级推理环境的整套依赖。
python3 -m pip install modelscope

export MODEL_DIR="$HOME/models/GLM-5.1-w4a8"
bash scripts/download_glm51_w4a8.sh
```

脚本使用 `snapshot_download(model_id=..., local_dir=...)`；失败后用相同目录重新运行，由 SDK 复用已下载内容。可以设置 `MODEL_REVISION` 固定可用的模型 revision；未设置时使用 SDK 默认 revision，可能随仓库更新而变化。不会下载到当前 Codex 工作机，必须在目标下载机器执行。

下载后检查模型配置、量化描述、分片索引和非空分片，并保存 `download_provenance.json`。这是文件完整性辅助检查，不是逐个权重文件的独立校验和验证。SDK 自身负责下载。

## 2. 恢复推理环境与采集插桩

最省事的是沿用旧机器已经跑通的容器镜像和框架版本。记录：

```bash
python3 -m pip show vllm vllm-ascend torch torch-npu transformers
npu-smi info
```

官方 v0.18.0 文档列出 A3 镜像 `quay.io/ascend/vllm-ascend:v0.18.0-a3`；这只是无旧镜像时的环境起点，不代表和此前 dev 镜像、CANN、torch-npu 完全一致。应优先迁移原来匹配驱动的工作镜像，按照新机器 NPU 类型挂载驱动和设备。启动脚本默认假定已进入正确配置的昇腾推理容器。

**当前 UMMwithClient 仓库只有 Trace 消费/模拟工具，没有旧服务中完整的 Top-2400 采集插桩。启动脚本不会自动安装它。**

若旧机器/旧容器仍可访问，先备份此前修改的：

```text
/vllm-workspace/vllm-ascend/vllm_ascend/attention/sfa_v1.py
```

同时迁移它导入的自定义辅助文件。在新环境先找到实际加载的 vllm_ascend 位置，备份原文件，再对照版本迁移改动；不要跨版本直接盲目覆盖。

必须保留：原生 Top-2048 的实际注意力路径、Top-2400 参考候选与分数的采集、当前 sample marker、TP rank 过滤和落盘字段。只有 `[IndexerTrace] hook ready` 日志还不足以证明已经成功保存候选。

如果没有旧文件或包含插桩的工作镜像，需要重新实现和验证采集方法。本会话现有记录仅包含入口片段及落盘片段，无法从中恢复当时完整参考计算函数。不要把“恢复启动命令”误认为“采集代码也已恢复”。

## 3. 恢复历史启动命令

```bash
export MODEL_DIR="$HOME/models/GLM-5.1-w4a8"
export DSA_DUMP_DIR="$HOME/dsa_dump_dir"
export API_KEY='sk-1234'

# 查看恢复的命令，不启动、不打印 API key。
bash scripts/start_glm51_w4a8_trace.sh --dry-run

# 检查模型文件、环境包版本、实际 sfa_v1.py 位置及采集字符串标记。
bash scripts/start_glm51_w4a8_trace.sh --check-only

# 前台启动，建议在 tmux/screen 内执行。
bash scripts/start_glm51_w4a8_trace.sh
```

启动脚本恢复此前参数：端口 8088、DP1/TP16、expert parallel、seed 1024、served name `glm-5`、max-num-seqs 16、max-model-len 192000、max-num-batched-tokens 16384、显存利用率 0.92、Ascend 量化、chunked prefill、disable-custom-all-reduce、enforce-eager，以及 `glm47` 工具解析器和原 additional-config。

路径和资源参数可以用 `MODEL_DIR`、`TP_SIZE`、`PORT`、`MAX_NUM_SEQS`、`MAX_MODEL_LEN`、`MAX_NUM_BATCHED_TOKENS`、`GPU_MEMORY_UTILIZATION` 覆盖。TP16 需要对应设备/并行部署配置，不能只因为新机器卡数不同就认为改成任意 TP 都能容纳该模型。

`MODEL_DIR` 必须包含本地 `config.json` 和完整权重，脚本启动前检查，避免此前本地不存在的路径被 ModelScope 当作远程 repo_id 的错误。保持模型原生 `index_topk=2048`；2400 属于额外候选采集，不通过修改模型参数实现。

## 4. 恢复采集后先做小样本验收

先确认 `/v1/models` 可访问，再沿用原来的单请求推理脚本与 `text.txt`。长文本需要保证 prompt token 数加生成 token 数不超过 max-model-len。

在请求发起前，在**服务容器可见的同一个目录**建立：

```bash
mkdir -p "$DSA_DUMP_DIR"
printf '%s\n' 'migration_smoke' > "$DSA_DUMP_DIR/current_sample"
```

第一次仅生成少量 token，请求间串行，不要同时修改 `current_sample`。如服务和客户端处于不同容器，需要共享挂载 dump 目录。请求完成后移除 marker，避免后续其他请求混入同一 sample。

检查新产生的 `.pt` 是否同时包含：

```text
indices                       # 原生 Top-2048
candidate_indices             # Top-2400 候选
candidate_scores              # 对应参考分数
has_reference_candidates      # True
seq_lens_key / seq_lens_query
layer
```

充分长的上下文中，应检查原生有效索引 2048、参考候选 2400，且 `seq_lens_query=[1]`；候选覆盖率/参考重合数用于诊断，不应不经核查就固定断言所有环境都完全一致。验证成功后再正式收集 100k 等长度样本，后续可用 `export_ppa_candidates.py` 对输入做进一步验证。
